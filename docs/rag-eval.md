# RAG 评估集（2026-09-13）

> 这份文档回答一个问题：**「推荐理由」从写死改成检索生成以后，怎么知道它没有变差？**
> 对应 `TECH_BACKLOG.md` 的 T15 第 4 步。跑法：`node scripts/rag-eval.mjs`。

## 为什么先做评估集

RAG 的失败方式很隐蔽：检索不到资料，模型照样能编一段通顺的话。所以要先有一把尺子，把
「检索到没」「引用对不对」「该拒答时有没有拒答」变成数字，再去改检索或接模型。

本项目已有的资产正好是 RAG 里最贵的部分 —— **每个地点都带来源链接和置信度**。
语料由 `scripts/build-rag-corpus.mjs` 从原型的地点数据自动导出：25 个地点（11 个粉丝关联 + 14 个官方观光），
总共只有 2,772 字，所以不需要向量库，BM25 足够。

## 评估集怎么设计

`data/rag-eval-set.json` 共 10 题，每题写清「问什么 / 期望命中哪些地点 id / 这题考什么」：

- **7 道可答题**：覆盖不同池别与问法 —— 专有信息（同款手串、生日餐厅）、拍摄地、口语描述（「可以直接和店员说要同款冰沙」）、观光场景（夜景喷泉、美妆购物）
- **3 道负例题**：语料里根本没有的内容，正确行为是**拒答**
  - 「济州岛租车自驾方便吗？」（语料只有首尔）
  - 「怎么从首尔坐火车去釜山？」（没有城际交通信息）
  - 「米其林三星餐厅求婚直升机怎么安排？」（**硬负例**：会字面撞到「餐厅」「安排」等词，专治"看起来像命中"）
- **3 个边界探针**（不计入指标，只看现象）：口语改写「想找个地方吃东西」、限定范围「同款餐厅」、专有名词「乙支路煤炭烧烤在哪」

## 指标定义

| 指标 | 定义 | 为什么这么定 |
|---|---|---|
| **检索命中率 Hit@K** | 期望来源是否出现在 Top-K 里（K=5） | 检索不到就什么都别谈，这是第一道关 |
| **引用正确率** | 回答里挂的每条 `[来源n]`，有多少条真的属于期望来源 | 直接对应"答案有没有引用错资料" |
| **拒答正确率** | 负例题是否拒答 ＋ 正例题是否被误拒答，除以总题数 | RAG 最容易被面试官问的一点：不知道的时候会不会装知道 |
| 引用结构自检 | 每条 `[来源n]` 是否都来自检索结果 | 防模型凭空造来源（接大模型后这条最关键） |

第一版（尚未接大模型）用 `scripts/lib/rag-answer.mjs` 的**模板回答**做占位：把 Top-3 检索结果拼成带
`[来源n]` 的回答，低/中置信度的证据强制加上「有粉丝提到，尚未人工核验」的措辞。
第 3 步接入大模型时只替换这个函数，**评估集和判定逻辑不用改** —— 这就是刻意留出的接缝。

## 结果

| 指标 | 修复前 | 修复后（当前） |
|---|---|---|
| 检索命中率 Hit@5 | 100%（7/7） | 100%（7/7） |
| 引用正确率（可答题） | 82%（9/11 条引用） | 82%（9/11 条引用） |
| 拒答正确率 | 90%（负例 2/3 拒答） | **100%（负例 3/3 拒答，正例 0 误拒答）** |
| 引用结构自检 | 通过 | 通过 |

## 评估集抓到的第一个真问题（这次最有价值的产出）

问「米其林三星餐厅求婚直升机怎么安排？」时，语料里根本没有相关内容，但检索层**照返回了 4 条结果**、
生成层照着它们写了一本正经的建议 —— 因为文档只要撞上「餐厅」或「安排」一个词就进了候选。
这就是最典型的 RAG 事故：**检索失败，但答案看起来很自信**。

修复（`scripts/lib/rag.mjs`，等价于 Elasticsearch 的 `minimum_should_match`）：

- 查询里有 2 个以上不同的词时，文档**至少命中 2 个不同的词**才算候选
- 短查询（1–2 个词）仍允许只命中 1 个词，避免把「汉江」这种单词查询误伤
- 之上再叠加原有的相关性阈值 `max(1.5, 最高分 × 0.35)`

结果：拒答正确率 90% → 100%，同时**检索命中率和引用正确率没有回退**；另外抽了 11 条评估集之外的
查询（咖啡 / 美食 / 汉江 / 金浦烧烤 / 寺庙手串 / 圣水快闪 / 夜店酒吧…）结果全部合理，
「酒店住宿」「机场大巴」「拍照好看的地方」这类语料里确实没有的，照常拒答。

## 已知短板（写进下一轮待办）

1. **口语改写抓不到**：`想找个地方吃东西` → 0 命中。关键词检索的固有边界，要靠向量检索或同义词表补
2. **排序还有噪声**：引用正确率 82% 的失分几乎都来自 Top-K 里的弱相关项（如问手串时带出快闪店）
3. **样本只有 10 题**：单题影响大（q08 一题就占拒答正确率的 1/3），补到 30 题更稳
4. **还是模板回答**：等接入大模型后，要用同一套判定重跑一遍，确认「生成」这一步没有把检索的好结果写坏

## 复现方式

```bash
cd outputs/interest-mcp
node scripts/build-rag-corpus.mjs        # 重新生成语料（改了地点数据后跑）
node scripts/rag-search.mjs "同款 餐厅" --k 5
node scripts/rag-play.mjs                # 交互式检索
node scripts/rag-eval.mjs                # 跑评估集，打印三项指标 + 写 data/rag-eval-report.json
node scripts/rag-eval.mjs --show-answers   # 额外打印每题的回答与引用
```

装了 npm 的环境也可以用 `package.json` 里对应的 `npm run rag:corpus / rag:search / rag:play / rag:eval`。

相关文件：`data/rag-eval-set.json`（题面）· `data/rag-eval-report.json`（当前报告）·
`data/rag-eval-report-baseline.json`（修复前基线，用于对照）· `scripts/rag-eval.mjs`（评估器）·
`scripts/lib/rag.mjs`（检索 + 两道闸门）· `scripts/lib/rag-answer.mjs`（回答组装层）
